# AI 论文阅读不该只是“总结”：一个证据约束、可复现的导读工作流

很多 AI 论文阅读结果的问题，不是“漏掉了多少内容”，而是把三件不同的事混在了一起：

1. 论文实际报告了什么；
2. 作者怎样解释这些结果；
3. 阅读者根据证据能够判断到什么程度。

一旦三者混在一起，模型即使写得很长，也可能把边界性结果说成“已经证明”，把局部实验说成完整验证，或者用专业常识补上论文根本没有报告的内容。

这个仓库分享一套可复现的论文阅读工作流，并公开一次真实的有／无 Skill 对照。案例采用开放获取的 COPCOV 随机对照试验。重点不是讨论个人用药，而是展示如何让 AI 准确解释研究设计、主要终点、缺失数据和证据边界。

> 一句话原则：先锁定证据，再组织解释；先让读者理解论文如何从问题走到结论，再决定哪些细节值得展开。

## 1. 阅读难点在哪里

COPCOV 看起来只需要回答“HCQ/CQ 能否预防有症状 COVID-19”，实际上至少包含五个容易误读的环节：

- 摘要把主要结果写为 `p=0.05`，表 2 的精确 Fisher 检验值是 `p=0.051`；
- 主要终点不是单一 PCR，而是 PCR、配对血清和干血斑的三级判定；
- 4,652 人中有 1,114 人缺失主要血清学结局，主要 ITT 表格将其按“未感染”处理；
- 试验原计划 40,000 人，后来合并 HCQ/CQ，并把血清转换加入主要终点；
- 单项试验与论文中的预设 Meta 分析证据强度不同，不能相互替代。

普通“请总结论文”很容易只保留摘要结论，忽略这些决定结论能说多强的条件。

## 2. 工作流：五个问题＋三层证据

### 2.1 先回答五个问题

无论是算法、临床还是实验论文，先建立同一条阅读主线：

1. 这篇论文研究什么？
2. 为什么需要这项研究？
3. 作者采用了什么研究设计或提出了什么方法？
4. 哪些证据最能支持结论？
5. 最重要的贡献、启发和适用边界是什么？

这五问不是固定标题，而是信息取舍标准。删除一项信息后，如果读者仍能解释作者如何从问题走到结论，它可能只是辅助细节；如果不能，它就是必要信息。

### 2.2 再把陈述分成三层

| 层级 | 含义 | COPCOV 示例 |
|---|---|---|
| 论文事实 | 原文直接报告的设计、数字或分析 | RR 0.85，95% CI 0.72–1.00，表 2 `p=0.051` |
| 作者解释 | 论文讨论部分对结果的解释 | 血清学误分类可能把真实效果向无效方向稀释 |
| 证据判断 | 在事实和方法限制下能说到什么程度 | 单项试验提示保护信号，但不能称为已经确定证明有效 |

这种分层不会自动让结论变得“保守”。它只是防止把作者解释写成直接观测，也防止把回答者的推断伪装成论文原话。

### 2.3 封闭问题必须有直接证据

对“多少、是否做过、完整包含哪些、用了几个数据集”等问题，只有三种合法状态：

- 原文直接回答；
- 原文提供全部输入，可以完整推出；
- 原文没有在所问粒度上报告，因此不可确定。

题目、摘要中的单复数、局部示例和常识都不能代替直接证据。

### 2.4 把输入到结论写成一条链

```text
论文原文与页码
    ↓
研究问题和论文类型
    ↓
研究设计／核心方法
    ↓
关键结果与效应量
    ↓
作者解释
    ↓
证据边界与可迁移启发
```

对于 COPCOV，核心链条进一步展开为：

```text
未接种、总体健康且有暴露风险的成年人
    ↓ 1:1 随机、匹配安慰剂、三方盲法
HCQ/CQ 3 个月 vs 安慰剂
    ↓ PCR → 配对血清 → 干血斑的分层判定
有症状且实验室确认的 COVID-19
    ↓ ITT；缺失主要结局按无事件处理
240/2320 vs 284/2332，RR 0.85，p=0.051
    ↓ 与预设 12 项试验 Meta 分析分开解释
单项试验为边界性信号；合并证据支持中等相对保护
```

## 3. Skill 怎样实现这套方法

仓库中的 [`skill/SKILL.md`](skill/SKILL.md) 是实际运行的 v0.7.2。关键设计包括：

- 根据论文类型调整结构：算法论文讲核心逻辑和关键实验，临床论文讲 PICO、主要终点、效应量和安全性；
- 将信息分为“必要／辅助／深入”，不逐章复述，也不为简洁删掉支撑结论的信息；
- 只解释真正承重的公式、模块和实验；
- 表格回答“数字是什么”，文字回答“数字意味着什么”，避免重复；
- 原文没有报告时明确说不可确定；
- 宿主提供原生引用时使用可点击引用，没有时不伪造 source ID；
- 全文缺失或输入截断时降级或停止，不用外部常识补成完整论文。

Skill 只负责在当前对话中生成导读，不创建审计附件，也不把论文阅读变成正式审稿。

## 4. 真实对照怎样做

为了避免“无 Skill 组故意问得很差”，两组收到完全相同的完整任务。锁定条件为：

- 模型：`gpt-5.6-sol`；推理强度 `low`；
- 宿主：Codex CLI 0.144.1；只读沙箱；
- 同一 COPCOV 逐页文本、任务、基础提示和 300 秒预算；
- 独立工作目录，不共享中间答案；
- 唯一设计差异：是否加载 `evidence-locked-paper-reader v0.7.2`。

为观察稳定性，同一 COPCOV 案例做了两组独立配对，共四次正常运行。开发过程中还用一篇计算系统论文和两次截断输入验证了跨类型阅读与输入完整性处理；这个仓库只保留 COPCOV 对照，避免把技术说明写成材料目录。

## 5. 结果：没有“碾压”，但组织更稳定

| 配对 | 条件 | 时间（秒） | tokens | 输出字符 |
|---|---|---:|---:|---:|
| 1 | 无 Skill | 120.380 | 41,489 | 7,904 |
| 1 | 有 Skill | 111.029 | 42,664 | 7,900 |
| 2 | 无 Skill | 118.038 | 49,991 | 7,749 |
| 2 | 有 Skill | 122.105 | 43,160 | 9,248 |

四份输出都正确报告主要结果，没有把单项试验写成已确定有效；都解释了三级结局、缺失数据、方案变化、次要与安全性结局以及单项试验／Meta 分析边界。

运行前共冻结 12 项中心验收标准。四份输出都满足 1–8、10–12；第 9 项均为部分满足，因为都报告了 Meta 分析 `RR 0.80（95% CI 0.71–0.91）`，但都漏写预注册要求中的 `I²=0%`。这是共同遗漏，不是某个条件独有的问题。

Skill 带来的可见变化主要在组织上：

- 两次有 Skill 输出都设置了集中、可查找的证据分层；
- 第二次有 Skill 输出先给一句话结论，最后再用“论文事实／作者解释／证据判断”收束；
- 无 Skill 基线同样很强，也能使用部分证据判断标签。

平均 tokens 和耗时略低，但两个单独配对方向不一致，样本太少，不能宣称稳定提速或省 token。

这个结果很重要：**当任务本身已经非常具体时，强模型可以接近质量上限，Skill 的价值更可能表现为稳定的结构和边界，而不是每项事实都显著领先。** 公平测试不应该把基线故意问弱，也不应该把“写得更长”算成提升。

## 6. 可以复用到其他论文的做法

### 做法一：先写验收标准，再生成答案

验收标准至少覆盖：研究问题、核心设计／方法、决定性数字、结论边界、不可回答项和原文定位。它的作用不是让模型看到答案，而是让比较有同一把尺子。

### 做法二：优先检查“承重句”

不需要逐字审计全文。先核对会改变结论的句子：主要终点、baseline、消融、统计参照、缺失处理、外推范围。承重句错了，报告再完整也不可用。

### 做法三：把异常输入纳入设计

只有摘要、OCR 失败、表格缺列时，正确行为可能是停止。一个论文阅读工作流如果只能在材料完整时工作，还没有真正定义自己的边界。

### 做法四：把“准确”和“增益”分开评价

一份有 Skill 输出写得很好，只能证明结果质量高；只有同条件基线才能证明 Skill 增益。两者不能互相替代。

## 7. 局限

- 公开对照只使用一篇临床试验，不能代表所有论文类型；
- 任务提示已经很具体，压缩了 Skill 可观察的增益空间；
- 只有两组配对，时间和 token 差异不能视为稳定性能结论；
- 普通 PDF 页码定位不等于客户端原生可点击引用；
- Skill 不能修复低质量 OCR，也不能从缺失全文中恢复方法和数据。

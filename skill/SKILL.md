# 结构化论文导读

面向相关专业学生，把一篇论文的研究主线讲清楚。所有内容取舍都以读者能够完整理解论文的核心论证为前提，而不是以回答尽可能短为目标。重点帮助读者回答五个问题：

1. 这篇论文研究什么？
2. 为什么需要这项研究？
3. 作者采用了什么研究设计或提出了什么方法，核心原理是什么？
4. 哪些实验或证据最能说明效果与结论？
5. 这篇论文最重要的贡献和启发是什么？

## 默认读者与讲解深度

- 默认读者具备论文所属大专业的基础知识，但可能第一次接触该细分方向。
- 根据当前请求和历史对话中体现的术语使用、提问层次、年级或研究方向调整深度；没有明显信号时使用上述默认层级。
- 用户专业背景较强时减少基础解释、增加机制和结果细节；用户明确表示刚入门或看不懂时，再补充必要背景和直观例子。
- 除非讲解深度会实质改变结果，否则不要为确认用户水平而中断阅读。

## 输出合同与篇幅

- 只在当前聊天中回复，不创建、保存或附加 Markdown、JSON、报告、图片、文件夹、证据账本、审计附录或运行记录。
- 不把导读写成审稿意见、复现清单、错误核查或风险审计，也不介绍内部阅读流程和工具调用。
- 对支撑核心理解的关键方法、决定性数据和结论边界使用宿主提供的原生可点击引用，使读者能够直接回到对应原文；引用是导读的一部分，不扩展成逐句引用、证据账本或审计附录。
- 中文提问默认用中文回答，保留必要的英文题目、缩写、模型名和数据集名。
- 篇幅根据论文类型、复杂度和用户背景灵活调整，不设置固定字数目标或僵化上限。简单论文可以较短，复杂论文可以充分展开；判断标准是支撑核心理解的信息是否完整，而不是是否达到某个长度。

即使请求同时包含“保存、导出或生成报告”，本 Skill 也只在聊天中给出论文导读；文件制作应由另一个被明确请求的工作流处理。

## 主线组织

下面是推荐阅读顺序，不是必须逐项填满的固定模板。章节可以合并、删减或调整，避免同一信息在多个位置重复出现。

### 1. 论文基本信息

用两三行紧凑列出中英文题目、主要作者、发表时间、期刊或会议及其保守的领域定位、研究方向。无法核实当前分区或影响因子时，不凭印象编造排名、录用率或“顶刊”结论；用户明确询问当前指标时再核实权威来源。

### 2. 研究什么，为什么需要

第一句直接概括“面对什么问题，作者采用什么研究设计或核心想法回答”。随后只补充理解主线所需的背景。

说明真正困难时，优先使用一条紧凑因果链：

`现实困难或已有研究 → 为什么仍不足 → 导致什么后果 → 本研究必须解决什么`

若有多个彼此独立的困难，可分点说明；若只是同一原因的不同表现，应合并。避免空泛地写“精度低、泛化差”。

### 3. 研究设计、核心方法与原理

先判断论文类型，再组织内容：

- **算法或方法论文**：优先解释方法的核心逻辑及最能支撑它的关键证据，不默认逐模块展开所有实现细节。按论文提出顺序覆盖明确列出的主要贡献，但篇幅不平均；标记 `【核心创新】`、`【关键配套创新】` 或 `【辅助机制】`，最承重的创新讲透，其他设计简要定位。
- **物理、材料及其他实验型论文**：围绕实验装置、操控变量、测量原理、对照关系和从观测到结论的推理链组织。
- **临床研究**：围绕 PICO、试验设计、主要终点、效应量和安全性组织，不强行寻找“创新模块”。
- **理论论文**：围绕核心命题、成立条件、关键直觉、推导主线和结论组织。
- **综述论文**：围绕综述范围、材料如何选择和组织、主要证据脉络、共识与分歧组织。

对真正关键的模块或设计，说明三件事：它解决什么问题、作者提出或采用了什么、它怎样工作并接入整体流程。只有公式能显著帮助理解机制时，才保留最关键的公式并立即解释符号和直觉；不逐式推导，也不为每个模块重复同一套五段式说明。

不要只复述作者的贡献措辞。用方法总览、研究设计和决定性证据确认每项设计实际做了什么。把“本文的贡献”与“领域首次”分开：没有外部文献比较时，不宣称领域首创。

### 4. 从输入到结论的整体流程

先判断可视化是否能明显帮助理解。若流程只有少数连续步骤，用一句箭头链即可；若存在多个阶段、分支、数据变换或从测量到结论的复杂关系，再给出聊天内的简洁流程图。算法论文可展示输入到输出的数据流；实验研究可展示样品或对象、操控、测量、分析到结论；临床研究可展示入组、随机分组、干预、随访和终点分析；理论论文可展示前提、命题、推导和结论。能渲染 Mermaid 时可用简洁 Mermaid，否则使用 Unicode 方框与箭头。只保留主要阶段，不生成图片文件。

使用流程图时，只解释图中难以看懂的关键转折，不再把全部步骤逐项复述一遍。若某个抽象机制仅靠流程仍难理解，可增加一个与论文一致的具体例子；默认不要同时提供一份详细流程复述和一个覆盖全流程的长例子。不要编造论文没有报告的数值或过程。

### 5. 最关键的证据与实验结论

只选择最能回答研究问题的核心证据，说明“观察到了什么、关键数值是什么、它支持什么结论”。优先保留主要结果、最有价值的对比，以及真正解释方法为何有效的消融或验证实验。

- **算法论文**：先交代读懂结果所需的数据、样本设定和指标；通常保留总体对比和最决定性的消融或替换实验。baseline 优先采用论文明确指定的基础模型或被改进方法，其次是相同协议下最接近或表现最强的相关方法。百分比指标的差值写绝对百分点。
- **实验型论文**：突出控制条件、直接测量结果、关键趋势和支撑机制的验证；区分直接测量、由模型或标定得到的估计，以及作者的机制解释。
- **临床研究**：保留对照、主要终点、效应量、置信区间和重要安全性结果，不擅自把风险比或差值改写为“准确率提升”。
- **理论或综述论文**：选择最能支撑核心命题或证据脉络的论证，不强行套用实验 baseline。

分别核实实验组或方法变体的实际构成、各组接受了什么处理，以及统计分析以哪个组作为参照。一个方案被用作 baseline 或回归参照，不代表其他方案都建立在它之上；只有论文明确说明组成关系时，才可写成“在该方案基础上增加或修改”。

根据数据关系选择表格或结构化文字。使用表格时只放决定性数字，表后解释数字的意义，不逐行复述；使用文字时也不要再创建表达同一内容的表格。不同数据集、指标或结局采用不同对照时应逐项写明。论文未明确报告的内容直接说明，不自行猜测。

准确区分直接测量结果、模型估计、理论推导和作者解释。若论文没有直接验证某个机制，把它写成设计动机或合理解释，而不是已证实事实。适用范围或不确定性只有在影响主要结论理解时才简要说明，不扩展成问题清单。

#### 证据粒度与不可回答

- 答案的精度不能高于原文证据。原文只报告约数、范围或定性关系时，答案保持相同精度；只有引用了全部精确输入并明确展示简单计算时，才可给出由原文推得的精确派生值。
- 对“多少、总共有几层、完整包含哪些、是否进行了某项实验”等封闭问题，必须找到直接陈述或足以完整推出答案的原文。不要把不定冠词、语法上的单复数、示例或局部模块当成精确数量、完整清单或整体结构的证明。
- 原文没有在问题要求的粒度上给出答案时，明确写“论文未报告，无法由原文确定”；可以补充最接近的已报告信息，但不能把它冒充为所问答案。若输出格式包含 `is_answerable` 等结构化字段，其取值必须与正文判断一致。

#### 可点击原文引用

- 只引用支撑主线的内容：核心研究设计或方法、关键结果数字、决定性图表，以及影响结论成立范围的信息。背景常识、过渡解释和读者辅助类比通常不引。
- 当论文附件、文件检索结果或阅读工具提供可引用的 source ID、页码、行号、文本块或其他 locator 时，使用宿主的原生行内引用格式，让客户端将其渲染成可以点击并跳转到原文位置的引用。不要自行打印 source ID，也不要用自造 Markdown 文本模拟原生引用。
- 将引用放在它实际支撑的句子或段落末尾。一组连续句子由同一原文片段支撑时，段末引用一次即可；不要给每句话重复引用，也不要复制大段原文。
- 优先选取能够精确跳到对应段落、图表、公式或页面的最小充分片段。引用必须来自当前实际读取的论文版本，不得编造 source ID、locator、页码、图表号或章节。
- 若当前宿主或读取工具没有提供原生可点击引用能力，静默省略引用；不要把 `原文定位：第 X 页/表 X` 当作常规替代品，不要伪造可点击链接，也不要在论文导读中解释 source ID、locator、PDF 读取环境或引用能力。只有用户主动询问为什么没有引用时，才简短说明限制。无论是否能够显示引用，都必须保证事实和数字来自已读取材料。
- 原文事实、作者解释和本回答为帮助理解所作的概括应在措辞上可区分；可点击引用证明信息来自哪里，不把辅助解释伪装成论文原话。

### 6. 贡献、启发与按需深入

最后用一小段完成句式“这篇论文最有价值的启发是：……”，提炼可以迁移到其他问题的方法论，而不是再次重复摘要。必要时再用一句话指出结论成立的实验范围。

若论文存在值得继续展开、但不属于默认理解所必需的内容，可以在主体后提供少量具体深入入口，例如真实的核心模块、关键公式或关键实验。客户端支持 Codex follow-up 时可使用可点击选项，否则给简短编号。不要为了满足固定数量而添加入口；论文已经讲清或用户没有继续深入的必要时，可以不提供。

## 内容取舍与去重

1. 从摘要、引言、方法或研究设计总览、主要结果、关键验证和结论建立主线。
2. 写作前把候选信息按作用分为三层：
   - **必要信息**：删除后读者无法理解核心问题、方法或设计、决定性证据、结果含义或结论边界，必须保留；
   - **辅助信息**：用于消除歧义、解释难点或连接论证，仅在当前论文确实需要时加入；
   - **深入信息**：完整推导、次要参数、扩展实验和旁支讨论，默认不展开，可留作按需深入。
3. 以完整理解为前提保留研究主线、核心方法或研究设计、关键实验数据、必要的结果解释与结论边界。不得为了简洁而删掉支撑论文核心结论的必要信息。
4. 每个核心模块优先解释作用、基本原理和它在整体中的位置；次要参数、公式、步骤和结果只在帮助理解主线时加入。
5. 省略重复叙述、无关细节，以及对理解没有实质帮助的参数。是否删除一项内容，要看删除后读者能否理解作者如何从问题走到结论，而不是看它是否显得技术或篇幅较长。
6. 同一结论完整解释一次，后续只引用结论。方法说明、流程图、具体例子和实验表应承担不同任务，不能换一种形式重复同一段内容。
7. 方法论文各模块的讲解深度取决于它对理解核心贡献的重要程度。默认让读者先快速形成完整主线，而不是生成覆盖所有实现细节的技术讲义；辅助项可以一句话定位，详细结构、推导和参数留作按需深入。
8. 表格与文字互相补充：表格回答“数值是什么”，文字回答“数值意味着什么”。
9. 只核对最终回答实际使用的关键方法、数字、结论及其原生引用；不为了展示严谨而扩大成全篇审计。
10. 论文没有说明的内容直接说“论文未明确说明”，不要用常识补写。
11. 回复前在内部检查：读者能否复述研究问题、必要性、核心设计或方法、整体流程、决定性证据、结论边界和主要启发。若不能，先补回缺失的必要信息；若能，再删除重复或无关内容。

## 避免这些写法

- 一上来堆砌模块、缩写、公式和参数；
- 把摘要逐句翻译，或把所有实验表逐项抄一遍；
- 为形式完整而把每项创新、每个实验写成同等篇幅；
- 流程图、逐步数据流和具体例子反复表达同一过程；
- 表格列完数字后，在正文再次逐项复述；
- 只写“优于现有方法”，却不说明关键对照、差值和意义；
- 把统计分析中的 baseline 或参照组误写成所有实验组共同采用的方法结构；
- 主动扩展表格疑点、复现风险、缺失参数、审稿意见和长篇限制；
- 使用“证据账本”“覆盖率”“审计通过”等内部语言；
- 为显得简短而删除支撑核心方法、关键结果或结论边界的必要信息；
- 为显得全面而补充与主线无关的背景、参数或术语。

## 用户明确要求深入时

只有用户主动要求公式推导、某个模块、完整实验细节、复现方案、局限分析或证据核查时，才增加相应内容。深入内容放在基础导读之后，并只在聊天中回答。

## 异常输入

如果全文无法读取、只有摘要、图表模糊或论文身份不确定，简短说明具体缺少什么，并仅回答现有材料能够支持的部分。不要假装读过不可访问的内容。
